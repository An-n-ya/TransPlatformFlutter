# 样式重构与多主题支持计划

## 一、概述（Summary）

本计划为 **YXing / TransPlatformFlutter** 项目建立可持续维护的样式与主题体系，核心目标：

1. **消除硬编码颜色**：当前项目中存在 **277 处** 字面量颜色（`Color(0xFF...)` / `Colors.xxx`），分散在 31 个文件。全部替换为基于 `Theme/ColorScheme` 的语义化引用。
2. **建立统一主题体系**：以 Flutter Material 3 原生主题机制为核心，实现 `ColorScheme.fromSeed` 的浅色/深色两套主题，并支持运行时切换（浅色 / 深色 / 跟随系统）。
3. **提升组件复用**：抽取跨页面重复的 UI 模式为可复用组件，减少样式冗余。
4. **保障质量**：建立验证机制、样式规范文档与回滚策略。

由于现有硬编码色绝大多数正是 **Material 3 2021 浅色方案的官方 token**（主色 `0xFF6750A4`、容器色 `0xFFEADDFF`、`0xFFE8DEF8`、背景 `0xFFFEF7FF`、错误色 `0xFFB3261E`、`onSurface 0xFF1C1B1F`、`onSurfaceVariant 0xFF49454F`、`outline 0xFFCAC4D0` 等），本方案无需重新设计色彩，而是**复用 M3 语义色**，把「散落的值」收敛为「统一的 ColorScheme 引用」，这样做改动最小、视觉保持不变、且天然支持深色模式。

## 三、目标架构（Target Architecture）

新增 `lib/theme/` 目录，核心职责分层：

```
lib/theme/
├── app_palette.dart        # 品牌色 token（种子色、非 M3 的品牌强调色）
├── color_schemes.dart      # light / dark 两套 ColorScheme（基于 seed 生成）
├── app_theme.dart          # buildLightTheme / buildDarkTheme → ThemeData
├── app_text_styles.dart    # 统一 TextStyles（对齐 textTheme，供页内直接引用）
├── app_spacing.dart        # 间距 & 圆角 & 尺寸常量
└── theme_provider.dart     # ThemeModeProvider (ChangeNotifier) + 持久化 + ThemeMode 扩展 helper
```

**关键设计原则**
- **页面依赖抽象**：页面一律通过 `Theme.of(context).colorScheme.xxx` / `textTheme.xxx` 取色与字型，**不再直接引用 `app_palette` 里的具体色值**。只有「品牌专属、ColorScheme 天然不涵盖」的极少数颜色(如渐变、Logo 背景)才引用 palette，且同样跟随主题提供浅深两态。
- **分工**：`ColorScheme` 承载语义(primary/error/outline/onSurface...)，`ThemeData` 承载组件级默认样式(InputDecoration、FilledButton、NavigationBar、AppBar 等)，`app_text_styles`/`app_spacing` 承载设计度量。
- **运行时可变**：`MaterialApp` 通过 `theme`/`darkTheme`/`themeMode` 三件套驱动，`themeMode` 由 `ThemeProvider` 状态决定。

## 四、技术选型（Technical Choices）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 主题范式 | Flutter Material 3 原生 `ThemeData` + `ColorScheme.fromSeed` | 现有硬编码色全部等于 M3 官方 token，原生方案零额外依赖、渲染器原生支持深色 |
| ColorScheme 生成 | 浅色 `fromSeed(brightness: light)`；深色 `fromSeed(brightness: dark)`；`dynamicSchemeVariant: DynamicSchemeVariant.fidelity` 保留品牌紫 | 主色一致，深色对比度自动满足可达性 |
| 主题状态管理 | 新增 `ThemeProvider extends ChangeNotifier`，与 `GlobalConfigProvider` 同范式，接入 `dependencies.dart` | 与现有应用级配置一致性最高、"新增复制成本"最低 |
| MaterialApp 重建 | `MultiProvider` 之外包一层 `Consumer<ThemeProvider>`，builder 返回带 `theme/darkTheme/themeMode` 的 `MaterialApp` | 满足 themeMode 切变时整个树重建 |
| 持久化 | `shared_preferences`（已依赖）保存 `theme_mode` 键（内嵌枚举：0 系统 / 1 浅色 / 2 深色） | 复用现有依赖，无需新包 |
| 主题切换入口 UI | 设置页新增「外观 / 深色模式」子页面，用 `SegmentedButton` 提供 浅色/深色/跟随系统 | 与 M3 风格一致，实现简单 |
| 回滚保障 | Git 分支 + 分阶段合入 + 逐页验证 | 见第七节 |

## 五、分阶段实施计划（Phased Implementation）

> 每阶段结束都应处于**可编译、可运行**状态；阶段 1–3 不改变任何视觉效果，阶段 4 引入切换能力。

### 阶段 0：基线锁定（前置）
- 新建分支 `refactor/style-theme`。
- 在浅色模式下全量截图清单（关键页面清单见 7.3 验证机制）作为重构前后对比基线。
- 记录当前 `git commit` 作为回滚点。

### 阶段 1：主题基础设施搭建（不触碰业务代码）
1. 新建 `lib/theme/app_palette.dart`：定义品牌种子色 `seed`（当前主色 `0xFF6750A4`）、深色模式的品牌强调色、少量非 M3 专属 token（Logo/渐变用，含 light/dark 两态）。
2. 新建 `lib/theme/color_schemes.dart`：`lightColorScheme` / `darkColorScheme` 两个 `const ColorScheme`（`fromSeed` 生成），并在注释中 **显式映射** 现用硬编码值到新 token（即「迁移对照表」），供阶段 2 逐项安全替换。
3. 新建 `lib/theme/app_theme.dart`：`buildLightTheme()` / `buildDarkTheme()`。
   - 通过 `theme.inputDecorationTheme` 统一输入框边框（圆角 4、聚焦色、错误态）；
   - `filledButtonTheme` 统一胶囊按钮默认样式；
   - `navigationBarTheme` 统一指示器色（替代 `app_shell` 中 `Colors.purple`）；
   - `textTheme` 挂载段落级字型，保证打印/排版一致。
4. 新建 `lib/theme/app_text_styles.dart`、`lib/theme/app_spacing.dart`：抽出项目高频度量（间距 4/8/12/16/24/48，圆角 4/8/12/16/24/100）。
5. 新建 `lib/theme/theme_provider.dart`：`enum AppThemeMode { system, light, dark }` + `ThemeProvider extends ChangeNotifier`，含 `load()`（读 SharedPreferences）、`setMode()`（写回并 notify）、并提供一个把 `AppThemeMode` 转为 `MaterialApp.themeMode` 的 helper。
6. 修改 `lib/config/dependencies.dart`：在 `_sharedProviders` 中加入 `ChangeNotifierProvider<ThemeProvider>(create: ...)`（并异步 `load()`）。
7. 修改 `lib/main.dart`：在 `MultiProvider` 之上包 `Consumer<ThemeProvider>`，builder 返回配置了 `theme: buildLightTheme()`、`darkTheme: buildDarkTheme()`、`themeMode: mode` 的 `MaterialApp`。默认 `themeMode` 保持 **跟随系统**。

**阶段 1 验收**：`flutter analyze` 无新增错误；深色模式下（系统切深色）整树已近似可用（因仍含硬编码浅色值，部分页面对比度偏低属预期，后续阶段逐步修正）；浅色模式视觉与基线一致。

### 阶段 2：颜色系统重构（278→0 的逐文件替换）
**替换通则（写入各文件注释与阶段说明）**

| 现硬编码值 | 替换为 `Theme.of(context).colorScheme.…` |
|---|---|
| `0xFF6750A4`、`Colors.purple` | `primary` |
| `0xFFEADDFF` | `primaryContainer` |
| `0xFFE8DEF8` | `secondaryContainer` |
| `0xFFFEF7FF` | `surface` |
| `0xFFECE6F0`、`0xFFE7E0EC`、`0xFFE9EDF1` | `surfaceContainerHighest`（或 `surfaceVariant`） |
| `0xFF1C1B1F`、`0xFF1D1B20` | `onSurface` |
| `0xFF49454F` | `onSurfaceVariant` |
| `0xFFCAC4D0`、`0xFF79747E` | `outline`（焦点细边框用 `outlineVariant`） |
| `0xFFB3261E`、`Colors.red` | `error` |
| `Colors.white` / `Colors.black`（前景、遮罩） | `onPrimary` / `scrim`（结合场景择一） |
| `Color(0x806750A4)` 等半透明 disabled | `primary.withValues(alpha: 0.38)` 或 `onSurface.withValues(...)`（用 M3 禁用规范） |
| `Colors.grey` 占位图标 | `onSurfaceVariant` 等 |

**替换策略**（降低改动风险）：
- 按「文件敏感度」分组，而非一次性全量：
  - **批次 A（低风险/无逻辑）**：登录、注册、密码重置、验证码、邮箱引导、欢迎引导页（auth/welcome/password 流，样式集中、逻辑简单）。
  - **批次 B（帖子/内容展示）**：`post_card`、`post_detail`、`interaction`、`comment`、`reply`、`add_post`、`add_topic`、`posts_page`、`topic_detail`、`search_page`。
  - **批次 C（用户/首页/杂项）**：`user_header`、`user_buttons`、`user_tabs`、`activities`、`notification_page`、`home_page`、`profile_page`、`app_shell`、`post_image_grid`、`step_progress_indicator`、`stat_button`、`search_field`、`topic_chip`、`user_avatar`。
- 每个页面：优先在 `build()` 顶部取 `final cs = Theme.of(context).colorScheme; final ts = Theme.of(context).textTheme;`，方法内复用。
- **处理并列写法**：因 `build` 出现顺序（a/b/c）会有属性顺序调整，**每个文件改完后必须单独 `dart format` 该文件**，把并列重排差异从 diff 中最小化。
- 删除阶段 1 迁移注释中已完成的对照项，仅保留仍在用的备注。

**阶段 2 验收**：全仓 `grep -E "Color\(0x|Colors\." lib/` 目标为 **0（或仅剩阶段 1 中定义的 `app_palette` 内的合法 token）**；每个页面深/浅色下对比度检查通过；`flutter analyze` 通过。

### 阶段 3：组件化提升
在 `lib/ui/widgets/`（或新建 `lib/ui/components/`）抽取跨页复用元素。建议按价值优先：

1. **`AuthTextField`**（必做，收益最高）：封装统一「56 高度、圆角 4、聚焦边框、错误态、prefixIcon、loading 禁用」的输入框，内部从 `Theme` 取色，注册/登录/email/code/reset 页全部替换为它。
2. **`PrimaryActionButton`**（必做）：封装胶囊 `FilledButton` + 可选 loader + 禁用态，替换所有登录/注册/提交按钮。
3. **`AuthScaffold` / 引导流程脚手架**：把 email_entry / code_verification / reset_password 共有的「浅底 + 透明 AppBar + 步骤指示器 + 居中卡片」抽成一个骨架，三个页面仅提供表单内容。
4. **`ErrorBanner`（错误提示文案）**、**`LabeledDivider`（带标签分隔线）**：登录页/注册页/欢迎页的"还没有账号?"分隔条抽成组件。
5. **`AppHeaderLogo`**：登录/欢迎页的圆角 Logo 头部块。
6. 清理步骤指示器、图片网格等组件内的**局部硬编码色**（阶段 2 批次 C 已含）。

组件内一律通过 `Theme` 取样式，保证后续改主题只需动阶段 1 的主题文件。

**阶段 3 验收**：上述组件被两个以上页面复用；`dart format` + `flutter analyze` 通过；组件页视觉与重构前一致。

### 阶段 4：主题切换功能
1. 新建「外观设置」入口与子页面（浅色 / 深色 / 跟随系统），挂在 `settings_page.dart`（`ListTile` + `SegmentButton` 或 `RadioListTile`）。
2. `ThemeProvider.setMode()` 写入 `SharedPreferences` 并 `notifyListeners()` → `Consumer` 重建 `MaterialApp`，全局即时切换。
3. **性能优化**：切换为 O(1) 状态变更，仅重建 `MaterialApp` 子树；无动画/无 ad-hoc 定时器。
4. **兼容性**：处理媒体查询默认值；测试大量内容页（图片网格深色底、头像圆角、易图查看器 `easy_image_viewer` 的深色背景适配——如需要给 `showImageViewerPager` 提供深色配置）。

**阶段 4 验收**：App 内任意页面可实时切换三种模式并持久化；重启后保持；全部关键页深色下可读性达标。

### 阶段 5：质量保障与收尾
1. **样式规范文档** `docs/style-guide.md`（或并入工程 README 相关章节）：「取色只能用 colorScheme / textTheme，禁止硬编码；新组件必须走 widgets 复用路径；度量使用 app_spacing」。同步加入 `analysis_options.yaml`：开启相关 lint（如避免 `Color(0x...)` 的约定，必要时自定义 `custom_lint` 规则，`custom_lint` 已在 dev_dependencies）。
   - **状态：已完成** `docs/style-guide.md` + `analysis_options.yaml` 已开启 `avoid_print / prefer_single_quotes / use_super_parameters / prefer_const_constructors / prefer_const_declarations / sort_child_properties_last / unnecessary_lambdas / prefer_final_locals`。
2. **测试策略**：补充样式相关的 widget 测试——`ThemeProvider` 序列化/持久化测试；若干关键组件（AuthTextField、PrimaryActionButton、label divider）在亮/暗两套 Theme 下的快照/渲染测试。

## 七、风险评估与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 逐色替换改变视觉 | 中 | 阶段 0 基线截图 + 逐页 diff 校验；每文件单独 `dart format` |
| 深色模式对比度不足（海报/图片等滚动内容） | 中 | 深色验收走 WCAG 对比度清单；图片容器统一 `surfaceContainerHighest` 底 |
| 404 边框/危险色误映射 | 低 | 迁移对照表逐项映射，先跑 `flutter analyze` + 自动 grep 校验 |
| 主题切换破坏既有页面 | 中 | M1 起即集成 `themeMode`，把风险前置暴露而非后置 |
| 双栈(provider/riverpod)状态冲突 | 低 | ThemeProvider 仅走 provider 与 `GlobalConfigProvider` 同路径，不引入 riverpod |
| 本机工具链阻塞（flutter SDK cache 写入 EPERM，`flutter analyze/test` 无法启动） | 中 | 用 `SDK/bin/cache/dart-sdk/bin/dart analyze` 绕过 flutter 引导做静态校验（已验证主题层零问题）；`flutter test` 待授予终端“完全磁盘访问”权限后执行 |

**回滚方案**：每阶段固定提交，逐里程碑合入 `refactor/style-theme`；任一步骤导致回归，直接 `git revert` 该里程碑 commit；`main` 上永远保留未重构基线 commit 作为最终兜底。

## 九、结论

本方案在**完全不引入新依赖、不改变浅色视觉**的前提下，通过复用 Material 3 原生主题机制，把 277 处离散硬编码收敛为统一的 `ColorScheme` 引用，并交付原生级深色模式与运行时主题切换。其改动风险通过「分阶段 + 逐页批处理 + 基线对照 + 可回滚提交」进行控制，最终为后续任何视觉调整或品牌重塑提供单一入口（只需改 `app_theme.dart` / `color_schemes.dart`）。
